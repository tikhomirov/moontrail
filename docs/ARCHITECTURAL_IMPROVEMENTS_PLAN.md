# План архитектурных и функциональных улучшений MoonTrail

Данный документ содержит дорожную карту инженерных улучшений пакета `tikhomirov/moontrail`, нацеленных на повышение безопасности, производительности, чистоты архитектуры (Dandy Code Style) и удобства интеграций.

---

## 1. Безопасность и защита данных (Security & Data Protection)

### 1.1. Авторизация доступа к просмотру Diff (`ActivityController::diff`)
- **Проблема:** Эндпоинт `GET /admin/moontrail/{activity}/diff` не проверял права на чтение сущности, допуская чтение истории любых моделей любым авторизованным пользователем админки (IDOR).
- **Решение:** Внедрить `ActivityAuthorizationResolver`, который проверяет права через Laravel Gate/Policy (`view`/`viewAny`) на объект `subject`. При отсутствии прав возвращать 403 Forbidden.

### 1.2. Маскирование чувствительных данных на уровне хранилища (Storage-level Masking)
- **Проблема:** Маскирование работало только при визуализации в UI. В БД (`moontrail_activity_log.properties` и `moontrail_model_versions.snapshot`) секретные данные (пароли, токены, ключи) могли сохраняться открытым текстом.
- **Решение:** Очищать поля из `sensitive_hide` и скрытые поля модели (`$model->getHidden()`) перед записью в БД в `MoonTrailObserver`, `VersionManager` и `DatabaseActivityLogger`.

### 1.3. Единый резолвер автора изменений (`MoonTrailAuthResolver`)
- **Проблема:** Рассинхронизация: `MoonTrailObserver` проверял guard MoonShine, а `VersionManager` обращался к `Auth::user()` (дефолтный guard `web`), что приводило к потере автора (`null`) при использовании кастомных гардов в MoonShine.
- **Решение:** Создать единый сервис `MoonTrailAuthResolver`, корректно извлекающий активного пользователя через MoonShine Guard с безопасным фоллбэком на стандартный Guard.

## 2. Архитектура и надежность (Architecture & Reliability)

### 2.1. Потокобезопасная приостановка обзервера (`withoutTracking`)
- **Проблема:** `MoonTrailObserver::$suspended` использовал глобальный `static bool`. В Laravel Octane / Swoole / RoadRunner статическое состояние сохраняется между запросами одного воркера.
- **Решение:** Добавить метод `withoutTracking(callable $callback): mixed` с гарантированным `try ... finally` и поддержкой локального контекста.

### 2.2. Плавная обработка ошибок отката (`RollbackController`)
- **Проблема:** Вызовы `abort(403)` и `abort(422)` после `toast()` приводили к показу системной страницы ошибки Laravel, скрывая всплывающие уведомления от пользователя.
- **Решение:** Заменить `abort(...)` на `redirect()->back()` с передачей сообщений об ошибке через Toast / Session flash.

### 2.3. Безопасная чанкованная очистка истории (`PruneMoonTrailCommand`)
- **Проблема:** Вызов `$query->delete()` на миллионных таблицах приводил к дедлокам и блокировке таблиц в БД.
- **Решение:** Реализовать пакетное удаление порциями (чанками по 500-1000 записей) в цикле.

### 2.4. Универсальное событие `ActivityLogged`
- **Проблема:** Отсутствовало событие при успешной записи аудит-лога, что затрудняло интеграцию внешних слушателей (нотификации в Telegram, аудит в SIEM, асинхронные вебхуки).
- **Решение:** Создать `MoonShine\MoonTrail\Events\ActivityLogged` и диспатчить его при логировании.
