# ТЗ-06: Ребрендинг пакета (отдельный этап)

## 0) Контекст

Цель пакета — продукт уровня «MoonShine Logs». На текущем этапе функционал и UI дорабатываются по ТЗ-01…ТЗ-04.

Ребрендинг выносится в **отдельный этап**, чтобы:

- не смешивать маркетинговые/пакетные изменения с функциональными
- снизить риски конфликтов при активной разработке

## 1) Цель этапа

Переименовать пакет и внешние упоминания так, чтобы:

- название продукта в UI/документации соответствовало новому бренду
- сохранилась обратная совместимость (минимально допустимая) для существующих пользователей
- релиз был предсказуемым (semver + миграционный гайд)

## 2) Исполнитель

- **Профиль:** тимлид / package maintainer
- **Компетенции:** Composer/Packagist, Laravel package development, semver, техническая документация

## 3) Требования

### 3.1 Новое имя

- Новое “продуктовое” имя: **MoonShine Logs**.
- Новое composer package name (предложение):
  - `tikhomirov/moon-trail`

Примечание:

- Финальное composer имя утверждается тимлидом (с учётом нейминга организации и доступности на Packagist).

### 3.2 Что должно измениться

Обязательно обновить:

- `composer.json`
  - `name`
  - `description`
- Namespace (по решению):
  - Вариант A (предпочтительно для обратной совместимости):
    - namespace **не менять** (оставить `MoonShine\MoonTrail\`), меняем только бренд/имя пакета
  - Вариант B (чистый ребрендинг):
    - сменить namespace на `MoonShine\AdvancedAuditLog\` и подготовить upgrade guide
- `README.md`
  - заголовок
  - quick start
  - ссылки
- `lang/en/ui.php`, `lang/ru/ui.php`
  - `activity_log` и прочие отображаемые строки (только где уместно)
- Config file name (по решению):
  - Вариант A: оставить `moontrail.php` (меньше breaking)
  - Вариант B: новый конфиг `moonshine-advanced-audit-log.php` + обеспечить миграцию
- View namespace:
  - сохранить работоспособность `moontrail::...` или мигрировать на новый (если выбрали вариант B)

### 3.3 Backward compatibility и миграция

Если меняется composer name:

- Обязательно добавить раздел `Upgrade guide` в документацию:
  - что заменить в `composer require`
  - какие конфиги/публикации обновить
  - что делать с кастомными рендерами/контрактами (bindings)

Если меняется namespace/config/view namespace:

- Это **breaking change**.
- Требуется:
  - upgrade guide
  - мажорная версия по semver

## 4) Проверка (Acceptance)

- Пакет устанавливается по новому имени (если переименован).
- UI в MoonShine показывает новое продуктовое имя (где применимо).
- `composer ci` проходит.
- Хост-приложение открывает:
  - `http://localhost:8000/admin/resource/moontrail-resource/index-page`
  - без ошибок в логах.

## 5) Definition of Done (DoD)

- Ребрендинг выполнен согласно выбранной стратегии (A или B).
- Обновлены README/локализация/описания.
- Есть upgrade guide.
- `composer ci` зелёный.
