# ТЗ-05: Финальная проверка выполнения всех ТЗ (Acceptance  Release Gate)

## 0) Цель

Этот этап является **обязательным финальным gate** перед тем, как считать пакет готовым к релизу/передаче в основную ветку.

Задача этапа:

- проверить, что выполнены ТЗ-01…ТЗ-04
- убедиться, что результат соответствует требованиям бизнеса (UI/UX, безопасность, rollback)
- убедиться, что пакет проходит CI (`composer ci`)
- убедиться, что в хост-приложении нет ошибок в логах

## 1) Исполнитель

- **Профиль:** QA engineer или Tech Lead
- **Компетенции:** Laravel, MoonShine, умение читать логи и воспроизводить сценарии в браузере

## 2) Предусловия

- Пакет установлен в хост-приложение (Laravel + MoonShine).
- Миграции выполнены.
- Есть минимум 1 модель, для которой включён трекинг (через `HasMoonTrail` или `auto_track_models`).
- В MoonShine меню доступен пункт Activity Log.

## 3) Проверка UI в браузере (обязательная)

### 3.1 Global Activity Log: Index page

Открыть:

- `http://localhost:8000/admin/resource/moontrail-resource/index-page`

Проверить:

- **Read-only**
  - отсутствуют кнопки Create/Edit/Delete/Mass delete
  - попытки открытия страниц редактирования/удаления (если URL известны) дают 403/не доступны
- **Таблица**
  - колонки соответствуют ТЗ-01
  - `Event` отображается badge’ом, локализация корректная
  - Subject/Causer отображаются читабельно
- **Фильтры** (если выполнено ТЗ-03)
  - есть фильтры: log/event/subject type/subject id/causer type/causer id/date from/date until
  - фильтры комбинируются
  - Reset очищает фильтры
- **Поиск**
  - поиск находит по description/event/subject_type
  - поиск находит по `properties` (best effort)

### 3.2 Global Activity Log: Detail page

Открыть detail любой записи.

Проверить:

- секции General/Relations/Changes/History присутствуют
- в Changes:
  - diff читаемый
  - скрытые/маскированные поля не раскрывают значения
  - JSON/array можно раскрыть (Expand) и скопировать (Copy)
- History:
  - timeline отображается
  - inline diff загружается при раскрытии и не делает повторных запросов при повторном раскрытии

### 3.3 Rollback UX (если выполнено ТЗ-04)

Проверить:

- если у пользователя нет прав rollback:
  - кнопок rollback нет
  - прямой POST на rollback endpoint возвращает 403
- если у пользователя есть права rollback:
  - кнопка rollback доступна
  - модалка подтверждения открывается
  - после подтверждения:
    - данные восстанавливаются
    - появляется toast об успехе
    - в истории появляется событие `rolled_back`

## 4) Проверка логов хост-приложения

После всех действий в браузере:

- проверить `storage/logs/laravel.log`
- критерий: **нет новых ошибок/исключений**, связанных с пакетом (routes, views, controllers, policies, query builder)

## 5) Проверка CI пакета

В корне пакета выполнить:

- `composer ci`

Критерий:

- `rector --dry-run` без изменений
- `pint --test` без ошибок
- `phpstan` без ошибок
- `pest` без падений

## 6) Итоговый чеклист DoD (Release Gate)

Считать пакет готовым можно только если:

- UI на `.../moontrail-resource/index-page` соответствует ТЗ-01
- rollback соответствует ТЗ-04
- фильтры/поиск/маскирование соответствует ТЗ-03
- `composer ci` зелёный
- логи хост-приложения чистые
