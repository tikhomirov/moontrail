# TZ-07 — Финальная проверка выполнения всех ТЗ (Release Gate)

## 0) Краткое текущее состояние

Ядро пакета и большая часть UI уже реализованы. Для закрытия проекта нужен единый, строгий и проверяемый финальный gate, который подтверждает соответствие всем ТЗ V2 перед релизом.

---

## 1) Цель этапа

Подтвердить, что результат по этапам `TZ-01 ... TZ-06`:
1. соответствует требованиям;
2. стабильно работает в браузере;
3. не порождает ошибок в логах хост-приложения;
4. проходит полный CI-пайплайн пакета.

Без прохождения этого gate релиз запрещён.

---

## 2) Кто выполняет

- **Основной исполнитель:** QA engineer.
- **Ответственный за решение Go/No-Go:** Tech Lead.
- **Поддержка:** backend/UI разработчики для оперативного фикса дефектов.

Компетенции:
- Laravel + MoonShine;
- ручное тестирование админ-панелей;
- работа с браузерными DevTools (network/console);
- чтение логов и CI-отчетов.

---

## 3) Предусловия

Перед стартом финальной приемки обязательно:

- все этапы `TZ-01 ... TZ-06` помечены как «готово к проверке»;
- выполнены миграции в хост-приложении;
- есть тестовые данные activity/versioning (created/updated/deleted/rolled_back);
- доступен админ-пользователь с правами view и отдельный пользователь без rollback прав;
- приложение запущено локально и доступно по URL:
  - `http://localhost:8000/admin/resource/moontrail-resource/index-page`

---

## 4) Обязательная проверка в браузере

## 4.1 Global Activity Log — Index

Открыть:
`/admin/resource/moontrail-resource/index-page`

Проверить:

### 4.1.1 Read-only
- нет Create/Edit/Delete/Mass-delete кнопок;
- прямые попытки write-операций дают 403/недоступны.

### 4.1.2 Таблица
- колонки и порядок соответствуют `TZ-01`;
- Event в виде badge;
- Subject/Causer читаемы и корректно форматируются;
- сортировки ID/Date работают.

### 4.1.3 Фильтры и поиск
- все фильтры из `TZ-03` доступны;
- фильтры комбинируются (AND);
- Reset очищает фильтры;
- поиск работает по базовым полям и best-effort по `properties`.

---

## 4.2 Global Activity Log — Detail

Открыть detail произвольной записи.

Проверить:
- присутствуют секции General / Relations / Changes / History;
- Open-ссылки в Relations показываются только если ресурс найден;
- Diff читабелен, JSON раскрывается и копируется;
- hidden/masked поля не раскрывают секреты.

---

## 4.3 Timeline + Inline Diff

Проверить:
- diff грузится при первом раскрытии;
- при повторном раскрытии повторного запроса нет (кеш);
- корректные состояния loading/error/empty;
- отображение rollback-версий (`rolled_back`, ссылка на target version).

---

## 4.4 Rollback security + UX

Проверить двумя пользователями.

### Пользователь без прав rollback
- rollback кнопки не отображаются;
- прямой POST на rollback endpoint -> 403.

### Пользователь с правами rollback
- rollback кнопки доступны (кроме первой версии);
- открывается confirm modal;
- после подтверждения:
  - данные откатываются;
  - виден success toast;
  - в history появляется новая `rolled_back` версия.

---

## 5) Проверка логов хост-приложения (обязательная)

После всех браузерных сценариев:

- проверить `storage/logs/laravel.log`.
- критерий приемки: **нет новых ошибок/исключений**, связанных с:
  - роутами пакета,
  - контроллерами,
  - blade rendering,
  - authorization/policy,
  - query/filter/search логикой.

---

## 6) Проверка CI пакета (обязательная)

В корне пакета выполнить:

```bash
composer ci
```

Критерии:
- `rector --dry-run` без изменений;
- `pint --test` без нарушений;
- `phpstan` без ошибок;
- `pest` все тесты зеленые.

---

## 7) Формат финального acceptance-отчета

По итогам проверки сформировать отчет `docs/v2/ACCEPTANCE-REPORT.md` в формате:

1. Дата/окружение/версия.
2. Матрица проверки по этапам `TZ-01 ... TZ-06`:
   - статус: PASS/FAIL;
   - ссылка на доказательства (скрины/логи/тесты).
3. Browser checklist (PASS/FAIL по пунктам).
4. Logs check result.
5. `composer ci` result.
6. Список дефектов (если есть) с приоритетом P0/P1/P2.
7. Вердикт Tech Lead: **GO** или **NO-GO**.

---

## 8) Матрица Go/No-Go

## GO
Только если одновременно:
- все пункты browser-проверки PASS;
- rollback security PASS;
- logs clean;
- `composer ci` PASS;
- нет открытых P0/P1 дефектов.

## NO-GO
Если выполнено хотя бы одно:
- есть P0 дефект;
- rollback можно выполнить без прав;
- есть ошибки в логах, вызванные пакетом;
- CI красный.

---

## 9) Acceptance (DoD)

Этап считается завершенным только при наличии:
- заполненного `ACCEPTANCE-REPORT.md`;
- формального решения Tech Lead (GO/NO-GO);
- при GO — готовности ветки к релизу.

---

## 10) Что не входит в этап

- Разработка новых фич.
- Рефакторинг без дефектов/требований.
- Изменение scope ранее утвержденных ТЗ.
